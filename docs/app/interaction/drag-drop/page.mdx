# DragDrop <span className="docs__label">Atom</span>

A shared provider, handle, target and feedback surface for moving caller-owned records. The installed
MIT dnd-kit core 6.3.1 runtime owns sensors, pointer/touch tracking, cancellation, announcements and
focus restoration. Ceebee supplies measured semantic drop zones and discrete keyboard navigation.

## Usage

<DragDropDemo />

Wrap the controlled content in `DragDropProvider`. Give a `DragDropHandle` to each movable record
and a `DragDropTarget` to its bounded content. Targets default to before/after; `inside` enables a
middle zone and `insideOnly` makes the whole target a destination. The caller approves each intent
through `canDrop`, then changes its own data in `onDrop`. Approval is rechecked on release.

## Keyboard and touch

Space or Enter picks up and drops; Escape cancels. Down/Right choose the next measured valid zone,
Up/Left the previous one. Labels are announced by dnd-kit. Focus returns to the source handle when
it remains mounted. A caller using virtualization must reveal and focus the moved source explicitly
when its old handle unmounts. Worksheet leaves handle keystrokes to this interaction instead of
running grid navigation. Hover tooltips inside the provider are suppressed during dragging so Escape reaches cancellation. Handles disable touch scrolling locally; the surrounding content still scrolls.

Targets use real, separately registered geometry. Pointer movement outside valid zones cancels the
move on release. The primitive does not mutate data, change parents, save, expand branches, sort,
load offscreen rows or guarantee every virtualized destination is currently mounted. Native scrolling
and dnd-kit ancestor auto-scroll remain available; tree/cycle rules belong to the caller.

## Tokens

Shared control heights, spacing, foreground, link and brand-background colors, focus widths/offsets,
border/radius, shadow, typography and `--cb-z-tooltip` govern handles, target markers and the drag overlay.
