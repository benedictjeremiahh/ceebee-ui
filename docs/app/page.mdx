# @ceebee/ui

A complete application toolkit: 73 documented components, a token layer that repaints all of them
from one file, and the motion and onboarding pieces a plain component library leaves out. Published
to npm and imported — never copied into a project, so a fix reaches every app on `pnpm up`.

## The two entries

The package splits at the React Server Component boundary, and the split is deliberate: a
content-heavy page can be built from `@ceebee/ui` alone and ship no animation runtime at all.

- **`@ceebee/ui`** — server-safe. `Surface`, `Flex`, `Grid`, `Container`, `Text`, `Heading`,
  `PageContainer`, and the widgets: `Donut`, `Sparkline`, `BarMini`, `Leaderboard`.
- **`@ceebee/ui/client`** — carries `"use client"`. The whole interactive catalogue — `Button`,
  `Form`, `Input`, `Select`, `Table`, `Modal`, `Tabs`, and the rest — plus the app shell
  (`Sidebar`, `TopBar`), `CommandPalette`, `Checklist`, and the providers.

## What this library refuses to do

Saying no is what keeps it small enough to maintain alone.

- **No charting.** Widgets with no axis (`Donut`, `Sparkline`) ship here; anything
  with an axis or a scale belongs to your app's charting library.
- **No memory.** Whether a person has already completed an onboarding step is passed in by your app.
  The library never learns who your users are.
- **No second way to do the same thing.** Where a component already exists, there is exactly one of
  it. Anything superseded is removed rather than kept as an alias.
