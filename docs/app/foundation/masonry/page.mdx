# Masonry <span className="docs__label">Composition</span>

`Masonry` arranges children into ragged columns in normal document flow. Items pack vertically
within each column, unlike `Grid`, which preserves row tracks. The layout collapses to two columns
and then one column at the documented responsive breakpoints.

## Usage

<Demo layout="block" code={`<Masonry columns={3} gap={3}>
  <Surface padding="sm"><Text>Short item</Text></Surface>
  <Surface padding="md"><Text>Content with a little more height.</Text></Surface>
  <Surface padding="sm"><Text>Another item</Text></Surface>
</Masonry>`}>
  <Masonry columns={3} gap={3}>
    <Surface padding="sm"><Text>Short item</Text></Surface>
    <Surface padding="md"><Text>Content with a little more height.</Text></Surface>
    <Surface padding="sm"><Text>Another item</Text></Surface>
    <Surface padding="lg"><Text>A taller item keeps its own column height.</Text></Surface>
  </Masonry>
</Demo>

## Anatomy and boundary

The root is a plain `div`; each non-empty child is wrapped in a `.cb-masonry__item` with
`break-inside: avoid`. The wrapper preserves the child’s own semantics. Masonry has no semantic
role, focus or keyboard model, value state, dismissal, anchoring, or gesture contract. Use `Grid`
when row alignment matters; use `Flex` when distribution or alignment is the layout contract.

## Responsive behavior

The requested column count is used at the widest breakpoint. At `900px` and below Masonry uses at
most two columns; at `560px` and below it uses one. These are layout decisions, not interactive
state changes.

## Loading

`Masonry.Skeleton` keeps the column and gap contract while using varied Token-sized blocks to
preserve the ragged silhouette during loading.

## Tokens

`gap` reads `--cb-space-0` through `--cb-space-8`. Skeleton dimensions read
`--cb-control-height-sm`, `--cb-control-height-md`, and `--cb-control-height-lg`; no raw layout
values are part of the component contract.
