# Tree <span className="docs__label">Composition</span>

Inline hierarchical data with the ARIA tree keyboard model. Tree is client-bound because it owns
roving treeitem focus and can manage selected and expanded paths.

## Usage

Click a node to select it, then use the arrow keys: exactly one node holds the tab stop and the
arrows move it through the visible enabled nodes.

<Demo

      key: 'projects',

      content: '3',

## Interaction boundary

- **Role:** a `tree` containing `treeitem` nodes and nested `group` containers.
- **Keyboard and focus:** exactly one enabled visible treeitem has `tabindex="0"`; Arrow, Home, and
  End keys move that roving focus through visible enabled nodes. A selected visible enabled path
  initializes and synchronizes the roving item; Arrow Left skips disabled ancestors and otherwise
  leaves focus in place when no enabled ancestor exists.
- **State:** `expandedPaths` / `defaultExpandedPaths` own visible branches; `selectedPath` /
  `defaultSelectedPath` own the selected node. Both use encoded recursive key paths, such as
  `projects/active`, so repeated local keys cannot collide.
- **Dismissal:** none. It stays in document flow and branches change only through keyboard state.
- **Positioning:** no portal, anchoring, or collision handling.
- **Gestures:** clicking an enabled node selects it; pointer expansion is deliberately absent so the
  same focus model remains the only expansion contract.

Tree differs from `Collapse`: Collapse has independent disclosure buttons and ordinary document
flow panels; Tree has a composite tree role, one roving focus, hierarchical traversal, and selection.

## Nested branches

Paths are encoded from the root, so the same local key in two branches never collides: below,
`projects/settings` and `people/settings` are different nodes.

## Size and tone

Row geometry and the selected-node colour; neither changes the keyboard model.

<Demo
  layout="grid"
  code={`<Tree size="sm" tone="brand" nodes={nodes} />
<Tree size="lg" tone="success" nodes={nodes} />`}
>
  <Tree
    size="sm"
    tone="brand"
    aria-label="Small tree"
    defaultExpandedPaths={['projects']}
    defaultSelectedPath="projects/active"
    nodes={[{ key: 'projects', label: 'Projects (sm)', children: [{ key: 'active', label: 'Active' }] }]}
  />
  <Tree
    size="lg"
    tone="success"
    aria-label="Large tree"
    defaultExpandedPaths={['projects']}
    defaultSelectedPath="projects/active"
    nodes={[{ key: 'projects', label: 'Projects (lg)', children: [{ key: 'active', label: 'Active' }] }]}
  />
</Demo>

`content` is static supplementary node content, such as a count or status. Do not place buttons,
links, inputs, or any focusable element inside it; Tree cannot validate arbitrary React nodes at
runtime, so callers must preserve the node's one keyboard and selection contract. Sibling `key`
values must be unique at every branch; repeated keys are supported only in separate branches.

## Keyboard

| Key | Result |
| --- | --- |
| `Arrow Down` / `Arrow Up` | Moves to the next or previous enabled visible node. |
| `Arrow Right` | Expands a closed branch; when open, moves to its first enabled child. |
| `Arrow Left` | Collapses an open branch; otherwise moves to its parent. |
| `Home` / `End` | Moves to the first or last enabled visible node. |
| `Enter` / `Space` | Selects the focused enabled node. |
