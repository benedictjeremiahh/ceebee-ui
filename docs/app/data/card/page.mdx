# Card <span className="docs__label">Composition</span>

A non-interactive Surface for content about one subject. Card owns the cover, header, tabs, body,
grid, and actions anatomy; links, buttons, and Tabs inside those regions own every interaction.

## Usage

<Demo layout="block" code={`<Card
  title={<Heading level={3} size="lg">Release health</Heading>}
  extra={<LinkButton href="/releases" variant="ghost" size="sm">Open</LinkButton>}
  cover={<ReleaseCover />}
  actions={<LinkButton href="/releases/latest" size="sm">View release</LinkButton>}
  hoverable
>
  <Card.Meta
    avatar={<Avatar name="Ceebee UI" />}
    title="Version 0.6"
    description="All package and documentation checks passed."
  />
</Card>`}>
  <Card
    title={<Heading level={3} size="lg">Release health</Heading>}
    extra={<LinkButton href="#card-props" variant="ghost" size="sm">Open</LinkButton>}
    cover={(
      <Surface variant="gradient" hue="blue" bordered={false} radius="sm" padding="lg">
        <Text size="lg" weight="semibold">A stable frame for one subject</Text>
      </Surface>
    )}
    actions={<LinkButton href="#card-loading" size="sm">View release</LinkButton>}
    hoverable
  >
    <Card.Meta
      avatar={<Avatar name="Ceebee UI" />}
      title="Version 0.6"
      description="All package and documentation checks passed."
    />
  </Card>
</Demo>

The title is a region, not an automatically chosen heading. Pass the heading level that belongs in
the surrounding document. `hoverable` changes elevation only: it never gives Card a role, click
handler, or tab stop.

<Guidance
  do="Put links and buttons inside the Card, where their roles and keyboard behaviour remain honest."
  dont="Attach one click handler to a Card that also contains controls — one Enter press can trigger two actions."
/>

## Grid and nested cards

`Card.Grid` is a responsive grid container, unlike Ant's fixed-width grid cell. Its children stay
ordinary content and can contain nested Cards when a subject has clearly separated sub-sections.

<Demo layout="block" code={`<Card title={<Heading level={3}>Services</Heading>}>
  <Card.Grid minItemWidth="12rem">
    <Card nested bordered={false}>API</Card>
    <Card nested bordered={false}>Documentation</Card>
    <Card nested bordered={false}>Registry</Card>
  </Card.Grid>
</Card>`}>
  <Card title={<Heading level={3} size="lg">Services</Heading>}>
    <Card.Grid minItemWidth="12rem">
      <Card nested bordered={false}><Text weight="medium">API</Text></Card>
      <Card nested bordered={false}><Text weight="medium">Documentation</Text></Card>
      <Card nested bordered={false}><Text weight="medium">Registry</Text></Card>
    </Card.Grid>
  </Card>
</Demo>

## Tabs

Card stays server-safe. Pass the existing client `Tabs` into the `tabs` region so Tabs keeps the
controlled/uncontrolled value, roving focus, panel association, and reduced-motion rendering.

<Demo layout="block" code={`<Card
  title={<Heading level={3}>Account</Heading>}
  tabs={<Tabs items={accountTabs} />}
/>`}>
  <Card
    title={<Heading level={3} size="lg">Account</Heading>}
    tabs={(
      <Tabs items={[
        { value: 'profile', label: 'Profile', content: <Text size="sm">Profile details</Text> },
        { value: 'access', label: 'Access', content: <Text size="sm">Access settings</Text> },
      ]} />
    )}
  />
</Demo>

## Loading

<span id="card-loading" />

Use `loading` when an already rendered Card is refreshing; it replaces only the body and leaves the
header and actions stable. Use `Card.Skeleton` when the whole Card does not exist yet.

<Demo layout="block" code={`<Flex direction="row" wrap>
  <Card title="Refreshing" loading actions={<span>Actions stay</span>} />
  <Card.Skeleton withCover withActions meta />
</Flex>`}>
  <Flex direction="row" wrap>
    <Card title="Refreshing" loading actions={<Text size="sm">Actions stay</Text>} />
    <Card.Skeleton withCover withActions meta />
  </Flex>
</Demo>

## Props

<span id="card-props" />

<PropsTable rows={[
  { name: 'title / extra', type: 'ReactNode', description: 'Header regions. Card never guesses a heading level.' },
  { name: 'cover', type: 'ReactNode', description: 'Edge-to-edge media or visual above the header.' },
  { name: 'tabs', type: 'ReactNode', description: 'A composed Tabs instance; Card owns no tab state.' },
  { name: 'actions', type: 'ReactNode', description: 'Footer controls. Card owns their layout, not their behaviour.' },
  { name: 'size', type: "'sm' | 'md' | 'lg'", default: "'md'", description: 'Token-based region spacing.' },
  { name: 'variant', type: "'plain' | 'tinted' | 'glass' | 'gradient'", default: "'plain'", description: 'Surface material.' },
  { name: 'tone / hue', type: 'Tone / DecorHue', description: 'Semantic or decorative colour for the Surface material.' },
  { name: 'bordered', type: 'boolean', default: 'true', description: 'Covers Ant outlined and borderless cases.' },
  { name: 'hoverable', type: 'boolean', default: 'false', description: 'Visual lift only; never changes semantics.' },
  { name: 'nested', type: 'boolean', default: 'false', description: 'Tighter geometry for a Card inside another Card.' },
  { name: 'loading', type: 'boolean', default: 'false', description: 'Replaces the body with matching skeleton content.' },
  { name: 'asSection', type: 'boolean', default: 'false', description: 'Renders the root Surface as a section.' },
]} />

`Card.Meta` accepts `avatar`, `title`, and `description`. `Card.Grid` accepts the same `columns`,
`gap`, and `minItemWidth` geometry as `Grid`. `Card.Skeleton` mirrors Card's visual props and adds
`withCover`, `withActions`, `meta`, and `lines`.

## Keyboard

Card, Meta, and Grid add no keyboard behaviour because none is a control. Controls inside them keep
their native keyboard contract; a composed Tabs instance uses the Tabs keyboard map.

## Tokens read

`--cb-space-*`, `--cb-radius-*`, `--cb-border-width`, `--cb-border`, `--cb-shadow-*`,
`--cb-duration-base`, `--cb-motion-scale`, `--cb-ease-standard`, and the Surface material Tokens.
