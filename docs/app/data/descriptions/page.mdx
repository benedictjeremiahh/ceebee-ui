# Descriptions <span className="docs__label">Composition</span>

Label-and-value record details rendered with native `dl`, `dt`, and `dd` semantics. Descriptions
owns layout and visual treatment; it does not fetch, edit, or own any record state.

## Usage

<Demo layout="block" code={`<Descriptions title="Release details" columns={2} bordered>
  <Descriptions.Item label="Version">0.6.0</Descriptions.Item>
  <Descriptions.Item label="Status">Ready</Descriptions.Item>
</Descriptions>`}>
  <Descriptions title="Release details" columns={2} bordered>
    <Descriptions.Item label="Version">0.6.0</Descriptions.Item>
    <Descriptions.Item label="Status">Ready</Descriptions.Item>
    <Descriptions.Item label="Summary" span={2}>All package and documentation checks passed.</Descriptions.Item>
  </Descriptions>
</Demo>

Each `Descriptions.Item` contributes one label/value pair. `columns` is responsive: the grid
collapses from four to two columns and then one column at narrow widths. `span` changes geometry
only; it never changes the item's semantics or interaction contract.

<Guidance
  do="Pass already loaded values and put editing controls inside an Item when the consuming app owns that interaction."
  dont="Add request, form, or edit state to Descriptions; use a Recipe or an app-owned adapter for workflows."
/>

## Skeleton

Use `Descriptions.Skeleton` when the record layout exists before its values arrive. It mirrors the
same label/value anatomy and accepts `columns`, `layout`, `size`, `bordered`, and `items`.

## Keyboard and boundary

Descriptions, Item, and Skeleton add no keyboard behaviour: they are document-flow content, not
controls. Buttons, links, and inputs placed inside values retain their native contracts. This is
distinct from `Table` because Descriptions is a static record-detail list, not sortable/tabular
data; it is distinct from `Field` because it owns no form state or validation wiring.

## Tokens read

`--cb-space-*`, `--cb-text-*`, `--cb-leading-*`, `--cb-weight-*`, `--cb-border-width`,
`--cb-border`, `--cb-radius-md`, `--cb-fg`, and `--cb-fg-muted`.
