# Collapse <span className="docs__label">Composition</span>

A disclosure group for revealing related sections in place. Collapse owns the heading buttons,
expansion state, and associated panels; content inside each panel remains ordinary document flow.

## Usage

<Demo layout="block" code={`<Collapse
  defaultValue="summary"
  items={[
    { key: 'summary', label: 'Summary', children: <Summary /> },
    { key: 'activity', label: 'Recent activity', children: <Activity /> },
    { key: 'access', label: 'Access', children: <Access />, disabled: true },
  ]}
/>`}>
  <Collapse
    defaultValue="summary"
    items={[
      { key: 'summary', label: 'Summary', children: <Text size="sm">This release is ready for review.</Text> },
      { key: 'activity', label: 'Recent activity', children: <Text size="sm">Three checks passed today.</Text> },
      { key: 'access', label: 'Access', children: <Text size="sm">Only owners can edit access.</Text>, disabled: true },
    ]}
  />
</Demo>

Base UI supplies the disclosure button semantics, `aria-expanded` / `aria-controls` association,
and controlled or uncontrolled state. `headingLevel` lets the section headings fit their document
context without changing the interaction.

<Guidance
  do="Use Collapse when readers benefit from scanning several section headings before opening details."
  dont="Hide a required workflow step or an error behind a closed panel; disclosure must not make essential state easy to miss."
/>

## Interaction boundary

- **Role:** a group of disclosure buttons, each controlling one labelled panel.
- **Keyboard and focus:** native buttons enter the Tab order; Enter or Space toggles the focused
  disclosure. Focus does not move when a panel opens or closes.
- **State:** controlled with `value`, or uncontrolled with `defaultValue`. Single mode exposes one
  key or `undefined`; multiple mode exposes an array of keys.
- **Dismissal:** none. A panel changes only through its own disclosure button or controlled state.
- **Positioning:** panels remain in document flow; there is no anchoring or portal.
- **Gestures:** none beyond native button activation. Collapse adds no swipe or drag model.

Single and multiple expansion share this interaction contract. `multiple` changes how many of the
same disclosure panels may remain open; it is not a visual variant.

## Multiple expansion

<Demo layout="block" code={`<Collapse
  multiple
  defaultValue={['design', 'behaviour']}

  items={sections}
/>`}>
  <Collapse
    multiple
    defaultValue={['design', 'behaviour']}
    expandIconPosition="end"
    items={[
      { key: 'design', label: 'Design', children: <Text size="sm">Tokens and Skins own visual treatment.</Text> },
      { key: 'behaviour', label: 'Behaviour', children: <Text size="sm">Base UI owns disclosure behaviour.</Text> },
      { key: 'product', label: 'Product knowledge', children: <Text size="sm">Consumers inject it at the edge.</Text> },
    ]}
  />
</Demo>

For controlled single mode, pass `value="summary"` and receive a key or `undefined` from
`onValueChange`. With `multiple`, pass `value={['summary', 'activity']}` and receive an array.

## Keyboard

| Key | Result |
|---|---|
| `Tab` / `Shift+Tab` | Moves through disclosure buttons and any focusable panel content in document order. |
| `Enter` / `Space` | Opens or closes the focused panel. |

Arrow keys do not move focus between headings. This follows the current disclosure guidance and
keeps every heading button in normal document order.
