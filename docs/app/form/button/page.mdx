# Button

To trigger an operation.

## When to use

A button means an operation or series of operations. Clicking it triggers the corresponding
business logic. Use one primary button for the main action, default buttons for ordinary actions,
dashed buttons for adding actions, text buttons for secondary actions, and link buttons for links.

`danger`, `ghost`, `disabled`, and `loading` refine those action states without changing the button
contract.

The default loading spinner is decorative: a text button keeps its action name while loading
and during the spinner's exit animation. Give an icon-only button an explicit `aria-label`;
the spinner does not supply the action's name. Custom icons retain the semantics their caller
provides. Applications still own completion/error feedback and announcements.
The adapter applies at hydration and on later icon mutations; it does not change the
upstream server-rendered markup.

## Sizes

`small`, `middle` (the default), and `large` map to `--cb-control-height-sm`, `--cb-control-height-md`,
and `--cb-control-height-lg`. Each is `max()` of a preferred step (`--cb-control-height-base-*`) and
the active pointer floor, so a density scale can retune the ladder but never take a control under its
floor. On a coarse pointer — a touch screen — `--cb-control-floor` becomes
`--cb-control-floor-coarse` (2.75rem, 44px), so `small` and `middle` both reach 44px and `large` keeps
its 48px, with no per-control CSS. A pointer that hovers keeps `--cb-control-floor-fine` (2rem, 32px).
