# Modal

Display a modal dialog box with a distinct accessible title, optional description, content area,
and actions.

## When to use

When requiring users to interact with the application, but without jumping to a new page and interrupting the user's workflow, you can use `Modal` to create a new floating layer over the current page to get user feedback or display information.

Additionally, if you need to show a simple confirmation dialog, you can use App.useApp hooks.

Use `description` for explanatory copy below the title. Do not place a subtitle inside `title`:
assistive technology must receive a concise accessible name and a separate description. Focus
returns to the opening control even when a controlled consumer unmounts the Modal immediately.

The positioning wrapper and backdrop expose `cb-modal` and `cb-modal__backdrop` respectively.
Use the upstream `classNames` semantic slots for any other additive styling.

## Stacking

Most dialogs stay on the default `--cb-z-modal` rung. A dialog rendered by Drawer content
automatically moves to the documented above-drawer rung, with its backdrop; pass
`layer="above-drawer"` only to control an exceptional call chain deliberately. Popups the
dialog itself opens — date pickers, selects, dropdowns — inherit the rung through Ant's own
`zIndex`, so they resolve above the dialog rather than wedging underneath it.

A short follow-up Modal may open from a Modal without replacing the review behind it. Its backdrop
paints above the parent panel and below its own panel, so the active task is visually distinct.
Ancestry composes with elevated Drawer-backed dialogs and deeper modal parents; callers do not
manually increment a z-index. The panel/backdrop separation is derived from the semantic layer Tokens.
Styles supplied through the upstream semantic slots are retained; CeeBee owns the layer ordering.
Keep only one focused task at a time and prefer an inline section or a page for a long workflow.
The [WAI-ARIA modal pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) describes the
keyboard and focus expectations, including returning to the invoking dialog.

When an opener is removed, an enclosing `FocusRecovery` can supply an injected, ready-aware
section destination. A connected opener retains ordinary return focus; an explicit return-focus
opt-out disables the fallback too.

## Keyboard

- `Tab` and `Shift+Tab` move through focusable controls inside the modal.
- `Escape` requests dismissal when keyboard dismissal is enabled.
- After dismissal, focus returns to the control that opened the modal unless
  `focusable.focusTriggerAfterClose` is explicitly disabled.

## Do / don't

- Do pass a short `title` and supporting `description` as separate props.
- Don't build a stacked title-and-subtitle React node and pass the whole block as `title`.
- Do pass `layer="above-drawer"` only to control an exceptional overlay call chain deliberately.
- Do keep a nested Modal focused on one short task and return to its parent when finished.
- Don't build a long chain of dialogs, or put a Drawer inside a dialog, to work around page structure.
