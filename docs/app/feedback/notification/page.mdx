# Notification <span className="docs__label">Composition</span>

`Notification` is persistent, rich status feedback with a title, explanation, and composable
actions. It stays in normal document flow: the application owns placement, history, and lifetime.

## Usage

<Demo
  layout="block"
  code={`<Notification
  title="Import completed"
  description="Twenty records are ready for review."
  actions={<Button variant="outline" size="sm">View records</Button>}
/>`}
>
  <Notification
    title="Import completed"
    description="Twenty records are ready for review."
    actions={<Button variant="outline" size="sm">View records</Button>}
  />
</Demo>

## Tone

Tone chooses the presentation, the default icon, and the announcement urgency together: `danger`
announces as an alert, the quieter tones as a status.

<Demo
  layout="block"
  code={`<Notification tone="info" title="Import completed" />
<Notification tone="success" title="Backup verified" />
<Notification tone="warning" title="Quota nearly used" />
<Notification tone="danger" title="Sync failed" />`}
>
  <Flex gap={3}>
    <Notification tone="neutral" title="Export queued" description="It will start when the current job finishes." />
    <Notification tone="info" title="Import completed" description="Twenty records are ready for review." />
    <Notification tone="success" title="Backup verified" description="Every checksum matched the source." />
    <Notification tone="warning" title="Quota nearly used" description="92% of this month's allowance is gone." />
    <Notification tone="danger" title="Sync failed" description="The remote rejected the last three attempts." />
  </Flex>
</Demo>

## Actions

Actions are composed, not configured. A dismiss control is one of them: pass it through `actions`
and remove the item from application state yourself.

<Demo
  layout="block"
  code={`<Notification
  tone="danger"
  title="Sync failed"
  description="The remote rejected the last three attempts."
  actions={
    <>
      <Button size="sm" tone="danger">Retry</Button>
      <Button size="sm" variant="ghost" tone="neutral" onClick={dismiss}>Dismiss</Button>
    </>
  }
/>`}
>
  <Notification
    tone="danger"
    title="Sync failed"
    description="The remote rejected the last three attempts."
    actions={
      <>
        <Button size="sm" tone="danger">Retry</Button>
        <Button size="sm" variant="ghost" tone="neutral">Dismiss</Button>
      </>
    }
  />
</Demo>

## Boundary

Notification is server-safe and owns no timer, queue, portal, fixed position, storage, or dismiss
state. Supply action controls — including a dismiss control — through `actions`, then remove the item
from app-owned state. `Toast` remains the transient provider-managed stack; `Alert` remains inline
feedback tied to nearby content.

## Skeleton

`Notification.Skeleton` accepts `lines` and `withActions`, preserving the same icon, copy, and
action geometry without creating a live region or interactive control.

</Demo>

## Tokens

The component reads surface, border, shadow, radius, spacing, typography, control-height, and
semantic `--cb-tone-*` Tokens. It does not read the global stacking ladder because it does not
position itself.

<Guidance
  do="Keep a durable operational result visible until the surrounding application resolves or removes it."
  dont="Create a second timed toast queue or hide the only copy of important information after a timeout."
